Privacy Policy - Velora Focus

Last updated: September 2026

Overview

Velora Focus is a local-only Chrome extension that combines a Pomodoro timer, a distracting-site blocker with an "intention wall", a one-click distraction tab grouper, local streak statistics and local time tracking to help the user stay focused. It is designed with a privacy-first architecture.

Data Collection

Velora Focus does not collect, transmit, or store any user data on external servers. There is no analytics, no tracking, and no telemetry transmitted outside of the browser.

How Data Is Handled

  • Local storage only. All user preferences, API keys, focus session history, blocklists, intentions written on the wall, temporary allowances and time-tracking statistics are stored exclusively in chrome.storage.local on the user's device. Nothing is sent to any server operated by the extension developer.
  • No browsing history collection. The extension does not store URLs you visit. Its block rules match against user-chosen domains or patterns on the device, and its time tracker records only minutes per user-defined project -- never a list of pages visited. When a blocked site is redirected to the intention wall, the wall shows the blocked domain so you can decide; only the domain, your intention text and the chosen duration are saved locally.
  • No user accounts. The extension does not require or support user accounts, login, or registration of any kind.

External API Usage

The only external network request made by this extension is to api.groq.com, and only when the user explicitly clicks "Weekly summary". This request:

  • Uses the user's own Groq API key, which they provide and store locally.
  • Sends only aggregated numbers (session counts, minutes per project, current streak). No URLs, no intentions, no page content.
  • Is initiated exclusively by manual user action; there are no background, scheduled, or automatic API calls.

The extension developer has no access to the user's API key or focus data. Usage of the Groq API is governed by Groq's own terms of service and privacy policy.

Site Blocking and the Intention Wall

Site blocking is implemented with Chrome's declarativeNetRequest API. Rules live in chrome.storage.local and are enforced by Chrome itself. Instead of a bare error page, a blocked navigation is redirected to a page bundled inside the extension (wall.html). To make that redirect possible, Chrome requires wall.html to be declared as a web-accessible resource for the sites that may be redirected; because the user may block any domain, this declaration uses the <all_urls> match pattern. This is not a host permission and grants the extension no ability to read or change any website; it only allows a site the user chose to block to be sent to the extension's own local page. When the user writes an intention and picks a duration, a temporary allow rule is created and removed automatically by a local alarm. The extension never opens a site by itself.

Tabs and Tab Groups

The tabs and tabGroups permissions are used only when the user clicks "Group distraction tabs". At that moment the extension reads the URL of the tabs in the current window, compares them with the user's own blocklist, and moves matching tabs into a collapsed tab group named "Distractions". Tab URLs are not stored or transmitted. The extension never closes, reloads, navigates or injects code into tabs.

Changes to This Policy

If this policy is updated, the new version will be published alongside the extension update on the Chrome Web Store.

Velora Keys

If you also use Velora Keys and have approved this extension there, this extension can ask Velora Keys for your AI API key when it has none of its own saved. The request travels over Chrome's local messaging between your own installed extensions; nothing is sent to a server. The key is used for this extension's requests to the AI provider, exactly as if you had pasted it here, and this extension does not store it. You can revoke the approval in Velora Keys at any time.
